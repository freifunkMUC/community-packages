# ffmuc-ipv6-ra-filter

The package accepts router advertisements from `bat0` only from the selected batman-adv gateway (`batctl gwl`). IPv4 and IPv6 then use the same gateway.

- The filter applies to the clients (`FORWARD`) and to the node itself (`INPUT`).
- A Gluon gateway sends its router advertisements from its client MAC address, not from its originator address. The filter accepts the wired client MAC addresses that the gateway announces in the translation table (`batctl tg`).
- When no gateway is selected, or the gateway announces no client MAC address, the filter accepts all router advertisements. The node then does not lose IPv6. The filter does not use router advertisements to select the router.
- Fallback: the filter also accepts all other routers when the node has no IPv6 default route through the selected gateway for 30 seconds, or when no router advertisement of the selected gateway arrives for 180 seconds (3 times the maximum router advertisement interval of 60 seconds). An ip6tables counter (mangle table, chain `ffmuc_ra_count`) counts the router advertisements of the selected gateway. After 3 seconds without a default route through the selected gateway, the node sends a new router solicitation (`ifup client6`), and again after 10 seconds, because the router of a new gateway can start after the first router solicitation, and the first DHCPv6 request after a firewall reload can fail. The fallback stops when a new router advertisement of the selected gateway arrives. The filter does not wait for a default route through it: during the fallback, odhcp6c knows all routers, and netifd installs only one of their default routes. The filter then runs `ifup client6`, so that odhcp6c forgets the other routers. The node then does not stay without IPv6 while another router announces a prefix.
- The filter is updated when batman-adv selects a new gateway (`gw` uevent), once per minute, by a timer at the next fallback time (every 10 seconds during the fallback), and 3 seconds after a run in which the selected gateway announces no client MAC address yet.
- When the gateway changes on a node without a static client address, the node requests a new DHCPv4 lease and restarts `client6`. The node then drops the addresses and the default route of the old router at once.
- After a gateway change, the node also tells its clients that the prefixes of the old router are deprecated. It starts when a prefix of the new router arrives on the node, or 2 seconds after the first router advertisement of the new router (counter `ffmuc_ra_count`), at most after 45 seconds. The node does not wait for its own DHCPv6 result. It sends 3 router advertisements, 3 seconds apart, with `ra-goodbye`: router lifetime 0, preferred lifetime 0 and valid lifetime 600 seconds for each old prefix that the new router does not announce. The clients then use an address of the new router for new connections. Old connections continue until the valid lifetime ends. The node sends only out of the local client ports, not into the mesh (`bat0`) and not to `local-port`. The node does nothing when it has no local client ports.
- When a node changes from gateway client to gateway server (its uplink comes back), it also deprecates the prefixes of the old gateway on its clients. It sends router advertisements for 8 seconds with `uradvd`, with preferred lifetime 0 and valid lifetime 0 for each old prefix that it does not announce itself. The node saves the prefixes of the gateway only while `client6` uses DHCPv6. When its uplink comes back, `ffbs-mesh-vpn-parker` makes `client6` static (the own prefix) before batman-adv is in server mode, and the own prefix must not replace the old prefixes. It keeps the router lifetime of its own router advertisement daemon, so that the clients continue to use it as router. Clients that do not know a prefix ignore these router advertisements. The node does this only when its own daemon runs and announces a prefix, and when `/usr/sbin/uradvd` exists. While `uradvd` runs, an ip6tables rule (mangle table, `INPUT`) drops the router advertisements of the node itself, so that odhcp6c on the node does not add the old prefixes again.
- In both cases, the node also removes the old router on its local clients. The old router can still be alive, and then the clients keep their default route through it, but it drops the new source addresses. For each old router, the node sends 3 router advertisements, 3 seconds apart, in the name of that router: from its link-local address and MAC address, with router lifetime 0, and preferred lifetime 0 and valid lifetime 0 for each old prefix. The node gets the address from its own IPv6 default route and the MAC address from its neighbour table. It sends only out of the local client ports (wired client ports and client Wi-Fi), not into the mesh (`bat0`) and not to `local-port`, with the helper `/lib/gluon/ffmuc-ipv6-ra-filter/ra-goodbye`. It sends nothing when it does not know the MAC address of the old router.
- The node keeps its last router (link-local address and MAC address) and its prefixes in `/etc/ffmuc-ipv6-ra-filter.last`. It writes the file only when the router changes. After a reboot or a network reload, the node does not know the old router from its routes. It then uses this file, so that it can still remove the old router and deprecate the old prefixes on its clients.
- A node in batman-adv gateway mode (`batctl gw_mode` reports `server`) selects no gateway. On such a node the chain returns to `FORWARD` and `INPUT`. The package that makes the node a gateway (for example `ffbs-mesh-vpn-parker`) then handles the router advertisements.
- respondd reports the MAC address of the IPv6 default router of the node in `statistics.gateway6`. It reports nothing on a gateway node and when the node has no default router. Other packages also write `gateway6` (`ffbs-parker-respondd` reports the IPv6 address of its uplink), and respondd uses the value of the last module.

Do not install `gluon-radv-filterd` together with this package. Its chain accepts the router advertisements first.

### Tests

`sh tests/fallback-sim.sh` simulates the fallback with mock commands. It does not need a Gluon node. Run it with busybox `sh`, for example in an Alpine container.
